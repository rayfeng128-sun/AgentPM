# Project Architecture Rule

本文件是 Harness 执行层的架构适配说明，不重复维护通用架构原则。

## 主规则来源

通用架构原则以项目根目录的 `AGENT/ARCHITECTURE_RULES.md` 为准，包括：

- 项目目录职责
- 模块边界
- 前后端依赖方向
- 公共层与业务层边界
- 架构决策触发条件
- 架构文档要求
- 禁止无依据复杂化

## 本文件职责

本文件只补充 Harness 执行时与架构变更有关的落地要求：

- 架构变更必须先完成影响分析。
- 涉及模块边界、API、数据库、权限或跨模块流程时，必须走完整闭环流程。
- 架构调整必须同步更新 `docs/architecture/` 中对应文档。
- 架构变更必须在变更目录中说明范围、非目标、验证方式和后续风险。
- 不允许把多个无关架构调整混在同一个变更目录中。

## 与 AGENT 规则的关系

若本文件与 `AGENT/ARCHITECTURE_RULES.md` 出现冲突，以 `AGENT/ARCHITECTURE_RULES.md` 的通用架构原则为准；Harness 只负责补充当前项目的流程门禁和变更目录要求。
